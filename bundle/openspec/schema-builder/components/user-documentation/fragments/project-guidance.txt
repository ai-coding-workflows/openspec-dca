User documentation is an optional addition to native DDD delivery. Its maintained
source is user-documentation/ at the project root, outside openspec/. An explicitly
chosen existing project-root documentation path may be used instead; record it in
project instructions and preserve it. Resolve these paths from the project root,
not from the schema, change, or template directory. arc42 is independent and stays
under openspec/system-architecture/ when selected. Neither component enables the other.

With this component selected, review changes to user tasks, entry points, results,
permissions, configuration, and relevant errors. Existing documentation obligations
still apply; optional packaging never waives an accepted requirement. Organize pages
for readers rather than copying spec or component folders. Keep terms understandable,
conditions accurate, and unknown facts visible. Do not invent UI labels or defaults.

During planning/Apply, user-documentation/** and every mapped maintained user-doc
or publication target are read-only, including new pages. Stage proposed text,
images, navigation, and reference changes inside the selected change, normally in
user-documentation/. Prepare the existing non-checkbox Integration handoff; promotion
requires separate authorization. Requirement sync does not publish user documentation.
This component adds no native artifact, publisher, linter, or reconstruction workflow.
