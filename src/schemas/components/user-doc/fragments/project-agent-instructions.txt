### User documentation
Use the base documentation policy for readers, coherent units and check classes.
Installation/setup, operation, integration and use are in scope when relevant to
the actual readers; do not enforce separate books or a universal directory tree.
Keep one design map of audience/need, basis, action/target and checks. Apply delivers
mapped descriptive sources; review whole units, overlaps and navigation, not only
new paragraphs. Resolve review signals with reasons; publish no unfilled starters.
Keep warnings at the action; do not invent interface details. Distinguish actual
safe procedure tests from inspection/rendering. Base publication boundaries and
closure reconciliation apply; this component does not authorize deployment.
